# ГдеКлады: трек, оффлайн, JSON (21.11.2026)

## Новое

### 1. Автосохранение трека (js/app.js)
- Трек сохраняется в localStorage: пачками каждые 20 точек, плюс при
  уходе со страницы и при сворачивании приложения (pagehide/visibilitychange).
- При запуске трек прошлых выходов восстанавливается на карте (лимит
  20 000 точек), битые точки отбрасываются.
- При старте записи приложение спрашивает: продолжить текущий трек
  («ОК») или начать новый («Отмена», текущий очистится).
- Звонок, сворачивание или перезагрузка больше не теряют пройденное.

### 2. PWA: оффлайн и иконка (sw.js, manifest.webmanifest, иконки)
- Иконка приложения на рабочий стол телефона (192 и 512 px + maskable).
- Service worker кэширует оболочку приложения (HTML, CSS, JS, Leaflet)
  и тайлы карт по мере их просмотра.
- В поле без связи: приложение открывается, точки и каталог доступны,
  карта показывает те участки, которые уже смотрели с сетью.
- ВАЖНО: оффлайн работает при открытии по http(s) — хостинг (например,
  GitHub Pages) или локальный сервер. При открытии файла напрямую
  (file://) оффлайн-режим просто не включается, всё остальное работает.

### 3. Кнопка «JSON» заработала (js/app.js, js/import.js)
- Раньше кнопка «JSON» была без обработчика — теперь экспортирует точки
  И трек в kopar_spots.json (формат с полем app: "kopar-spots").
- Импорт понимает и GPX, и JSON: резервная копия заливается обратно
  целиком — точки и трек. Файл импорта принимает .gpx и .json.
- При импорте координаты валидируются строго (null и мусор отбрасываются),
  id не конфликтуют с уже сохранёнными точками.

## Фото находок и навигация к точке (21.11.2026, дополнение 2)

### Фото находок (js/photos.js — новый модуль)
- При отметке новой точки: кнопка «📷 Добавить фото» — фото сжимается
  (до 1280 px, JPEG 75%) и прицепляется к точке после сохранения;
  накопленные фото видны миниатюрами, можно снять до сохранения.
- У существующей точки — «📷 Фото» в попапе на карте.
- Полные снимки лежат в IndexedDB, миниатюры и счётчики — в localStorage:
  списки и попапы открываются мгновенно и работают оффлайн.
- Клик по миниатюре — полноэкранный просмотр (лайтбокс каталога).
- В списке находок — бейдж «📷N» (сколько фото у точки).
- Удаление точки удаляет и её фото. Если IndexedDB недоступен —
  fallback в localStorage.
- Мини-советы: фото сжимаются автоматически, место расходуется бережно.

### Навигация к точке (js/nav.js — новый модуль)
- В попапе точки и в списке находок — кнопка «🧭»: сверху экрана
  появляется панель со стрелкой, расстоянием и азимутом.
- Стрелка ведёт к цели: учитывает курс телефона, если компас доступен
  (на iOS запрашивается разрешение при первом использовании); без компаса
  — направление «север наверху».
- GPS поднимается автоматически, если ещё не был включён; ошибки
  показываются в панели, а не вылетают.
- Панель закрывается крестиком или при уходе со страницы.

## Оптимизация под ПК и телефон (21.11.2026, дополнение 5)

### Телефон
- Безопасные зоны: интерфейс не «заползает» под вырезы и «ушки» iPhone
  (topbar, поиск, панель навигации, тулбар, панель прицела и прозрачность
  учитывают safe-area insets).
- viewport-fit=cover — карта тянется на весь экран даже с вырезами.
- Инпуты 16px — iOS больше не дёргает экран автозумом при тапе в поле.
- Убран синий подсвет тапов (tap-highlight), touch-action: manipulation —
  отклик кнопок мгновенный, без случайного двойного зума.
- Текст в модалках/полях выделяется, интерфейс — нет.

### ПК
- Горячие клавиши: S — отметка точки, G — GPS, T — трек, L — слои,
  H — исторические снимки, C — список находок, M — меню, Esc — закрыть
  всё открытое (прицел, навигацию, панели, модалку). В полях ввода
  клавиши игнорируются.
- Правый клик по карте — окно отметки прямо в точке курсора (на ПК это
  точнее прицела); контекстное меню браузера при этом не всплывает.
- Ховеры тулбара, меню, карточек и кнопок — только при наличии курсора.
- Кнопки тулбара чуть крупнее, меню шире, модалка просторнее.
- Контент страниц (список находок, каталог монет) — читаемая колонка
  760px по центру на широких экранах.
- Аккуратные тонкие скроллбары в панелях и списках.
- Курсор карты — перекрестие (в тему приложения).
- «О приложении» теперь подсказывает горячие клавиши.

## Оффлайн-карта: сохранение кусочка карты (21.11.2026)

- В панели слоёв появилась секция «Оффлайн-карта»:
  - «💾 Сохранить видимую область» — сохраняет тайлы того, что сейчас на
    экране, на текущем зуме и на зум ниже (для контекста при отдалении);
  - счётчик сохранённого: ~N тайлов, дата и подложка;
  - «🗑 Очистить» — удаляет сохранённые тайлы.
- Как работает: тайлы загружаются пачками по 6, service worker сам
  складывает их в свой кэш (тот же, что и при обычном просмотре), а без
  интернета отдаёт оттуда. Лимит — 600 тайлов за раз, иначе предложение
  приблизить карту.
- Сохраняется текущая подложка: хотите и спутник, и схему — сохраните
  область дважды на разных подложках.
- Работает только при открытии по адресу (хостинг / установленное PWA):
  с файла на диске service worker недоступен, приложение честно об этом
  предупредит.

## Общий каталог через GitHub (21.11.2026)

- Приложение при запуске ищет файл catalog.json рядом с index.html
  (нужен хостинг: GitHub Pages). Если файл есть — его правки и
  созданные монеты/правители применяются для всех посетителей.
- Локальные правки устройства остаются поверх общего каталога: то,
  что вы насоздавали лично, не конфликтует с опубликованным.
- В админ-панели новая кнопка «📤 GitHub»: скачивает catalog.json с
  текущими правками, правителями и монетами. Файл кладётся в корень
  репозитория и коммитится — после пуша все видят обновление.
- Фото монет: работают и data-URL (встроенные), и пути к файлам
  репозитория (например img/имя.jpg) — путь весит ноль байт в
  catalog.json.
- Обновление каталога не мгновенное: правки нужно экспортировать и
  закоммитить. Данные живой карты (точки, фото находок, треки) остаются
  личными для каждого устройства — для общего хранения нужна база
  данных, это отдельная задача.


## Почему в списке монет не было названий и что исправлено (21.11.2026)

Причина не в разметке: в карточке монеты текст (название, редкость,
год, металл, вес) был и в DOM, и в стилях ничего его не прятало.
Телефон показывал старую версию coins.js из кэша service worker:
версия кэша не менялась, и после обновления файлов на GitHub браузер
продолжал отдавать прежние файлы.

Исправлено:
- Версии кэшей подняты: kopar-shell-v3 и kopar-tiles-v3. После
  следующего пуша в репозиторий все устройства при первом запуске
  онлайн скачают свежие файлы.
- Очистка оффлайн-тайлов переключена на новый кэш kopar-tiles-v3.
- Стили карточки в списке укреплены: название выводится отдельной
  строкой с переносом в многоточие при длинных названиях, под ним
  строка «год · металл · вес · состояние», высота карточки не меньше
  высоты превью. Текст в карточке больше не может потеряться даже при
  конфликте стилей.

## Настоящая причина пустых карточек найдена и исправлена (21.11.2026)

- В coinLi() блок с текстом (название, редкость, характеристики,
  краткое описание) создавался и наполнялся, но никогда не добавлялся
  в карточку: в коде отсутствовал li.appendChild(body). Из-за этого

  выбрасывался. Проявлялось во всех версиях, не зависело от кэша.
- Исправление проверено рендером приложения в браузере: карточка
  содержит превью, название с редкостью, строку характеристик и

## Погода на ПК: найдена причина и починено (21.11.2026)

- На ПК страница показывала «Не удалось определить место» и висла:
  при отказе в геолокации резервный способ искал центр карты через
  window.map, а карта была создана как const и в window не попадала.
  Теперь карта доступна как window.map (app.js).
- Резерв координат стал трёхступенчатым: GPS → центр карты → точка
  старта. Погода работает на ПК даже с полностью запрещённой
  геолокацией.
- Страница погоды стала неубиваемой: рендер обёрнут в try/catch,
  признак «занят» снимается в finally — страница больше не может
  зависнуть на «Догоняю небо…».
- Если сети нет и кэша нет — вежливое сообщение, при этом Солнце
  и Луна (они считаются локально) всё равно показываются.

## Защита админки: пароль нигде не хранится открыто (21.11.2026)

- Пароль больше НЕ лежит в localStorage открытым и не виден в коде:
  хранится только случайная соль + SHA-256 от «соль:пароль:соль».
  Подобрать по хэшу можно лишь перебором, пароль из кода не достать.
- Вход в админку теперь всегда по паролю. При самом первом входе
  приложение просит ПРИДУМАТЬ пароль (от 4 символов; можно длинный,
  с буквами — тогда подбор нереален). Старые устройства с сохранённым
  PIN мигрируют на хэш автоматически при первом же запуске.
- 5 неверных попыток — блокировка входа на минуту.
- Один общий вход для админок монет и старины (window.adminAuth).
- В модалке входа кнопка 👁 — показать/скрыть ввод.
- Честно: это браузерное приложение без сервера, поэтому от человека,
  который умеет править JS прямо в консоли, полная защита невозможна —
  но пароль теперь не виден ни в коде, ни в памяти, ни «через код элемента».
  Общий каталог это дополнительно страхует: catalog.json на GitHub
  может изменить только тот, у кого есть доступ к репозиторию.
- Версия кэша SW: kopar-shell-v10.

## Админка v2: прямая публикация на GitHub и новые функции (22.11.2026)

- «☁ На GitHub»: catalog.json отправляется прямо в репозиторий
  через GitHub API (нужен токен Fine-grained с правом
  Contents: Read and write — вводится один раз, хранится только
  на устройстве). Репозиторий определяется автоматически, если
  сайт открыт на github.io.
- Кнопка «🔑 Токен»: задать, сменить или удалить токен.
- Красная точка на «📤 GitHub» показывает неопубликованные
  правки — гаснет после успешной отправки.
- ⧉ Копия монеты: существующая монета клонируется в кастомную
  для правок (имя + «(копия)»).
- 👁 Проверка ссылки на фото в редакторе: ✅/❌ сразу.
- Стрелки ↑↓: порядок кастомных монет и правителей в каталоге
  монет, порядок эпох и предметов в старине. Порядок сохраняется
  и уходит в catalog.json.
- Кнопки «＋ Монета» и «＋ Правитель» в админ-баре теперь работают
  (раньше открывались только из шапки эпохи).
- Данные с GitHub больше не помечаются как «неопубликованные».
- Версия кэша SW: kopar-shell-v13.
